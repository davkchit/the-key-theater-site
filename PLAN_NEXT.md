## Принятые решения

- **n8n убираем.** Вся логика бота уже в `bot/core/lib.js` (чистые функции:
  `normalizeUpdate`, `decide`, `afterModel`, `startSignup`, `signupStep`, парсер).
  n8n был только транспортом. Заменяем маленьким Node-сервисом. Логика ответов
  НЕ меняется.
- **CMS остаётся Decap** (`public/admin/config.yml`). Directus не делаем.
- **Заявки:** письмо на почту театра + копия в SQLite на сервере + выгрузка CSV
  для Excel. Google Sheets (`src/data/sheetsForms.ts`) убираем — 152-ФЗ.
- **Знание бота** снова берётся с сайта (`public/knowledge.json`), а не из Word.
  Режим документов (`bot/core/docs.mjs`) оставить, но выключенным по умолчанию.
- **Модель:** пока Groq (ключи в `.env.bot`, ротация `LLM_KEY`, `LLM_KEY_2..9`),
  в проде — gpt-oss-120b в Yandex AI Studio. Переключение — только настройки.
- **Хостинг:** VPS David на reg.ru, на нём уже живут 2 других проекта. Домена
  пока нет — используем `<IP>.sslip.io` (HTTPS работает). Позже переезд на
  Beget VPS, поэтому всё в Docker.

## Правила работы

1. После любой правки `bot/core/lib.js`: `node bot/scripts/eval.mjs --dry`
   (без модели, бесплатно). Живые прогоны — только точечно (`--ids=...`) и
   только на ключе `EVAL_LLM_KEY` (его подхватывает `bot/core/llm.mjs`).
2. JS с обратными слешами и регулярками править через Edit/Write, **не** через
   python/sed heredoc — это уже ломало код несколько раз.
3. Секреты (`.env.bot`) не печатать в чат и не коммитить.
4. На VPS: сначала только смотреть. Ничего не останавливать, не удалять и не
   занимать порты 80/443, пока не выяснено, как подняты два других проекта.
   Любую команду, меняющую чужое, — сначала показать David.
5. Коммитить только когда David скажет. Ветка `master`.

## Этап 1. Сервис бота вместо n8n — `bot/server/`

Node 22+, без фреймворков. Зависимости: только `nodemailer` (этап 3).
База — встроенный `node:sqlite`.

Файлы:
- `bot/server/index.mjs` — точка входа: HTTP-сервер (порт `BOT_PORT`, по
  умолчанию 8787) + цикл long polling Telegram.
- `bot/server/lib.mjs` — загружает `bot/core/lib.js` так же, как
  `bot/scripts/simulate.mjs` (`loadLib`), и отдаёт функции.
- `bot/server/store.mjs` — SQLite (`bot/data/kluch.sqlite`): таблицы `chats`
  (chat_id, state json, updated_at), `leads` (те же колонки, что `TABLES.leads`
  в `bot/scripts/build-workflow.mjs`), `unanswered`.
- `bot/server/llm.mjs` — вызов модели с ротацией ключей. Взять логику
  `callLlm/limitInfo/pickKey` из `lib.js`, передав вместо n8n-хелперов объект
  `{ httpRequest }` на `fetch` (формат ответа: `{ statusCode, body }`).
- `bot/server/knowledge.mjs` — раз в 10 минут `GET ${SITE_URL}/knowledge.json`,
  проверка как в узле «Проверить и сравнить» (`build-workflow.mjs`), держать
  последнюю хорошую копию; на старте — `buildKnowledge(repoRoot)`.

Ход обработки одного сообщения — повторить то, что делал workflow
(`bot/scripts/build-workflow.mjs`, узлы от «Решить» до «Итог хода» и рассылки):
1. `ev = normalizeUpdate(update)`; прочитать state из `chats`.
2. `res = decide(ev, state, global, knowledge, { nowMs, adminChatId, useParser: true })`.
3. Если `res.parse` — вызвать парсер (`LLM_PARSER_MODEL`, бюджет 15 с), затем
   `decide(...)` ещё раз с `parsed` (при ошибке `parsed = null`).
4. Если `res.model` — вызвать модель (бюджет 50 с), `afterModel(res, text, nowMs, knowledge)`;
   при ошибке — текст «Я сейчас перегружен…» из узла «Модель недоступна».
5. Выполнить эффекты и сообщения — перенести логику узла «Итог хода»
   (`plan.chats / leads / statuses / unanswered / tg`) один в один.
6. Сохранить state. Сообщения одного чата обрабатывать строго по очереди
   (очередь на chat_id) — сейчас два быстрых сообщения могут перепутаться.

Telegram: long polling (`getUpdates`, как `bot/scripts/poll-telegram.mjs`),
вебхук не нужен — значит, не нужен и домен.

Ошибки: лог в `bot/data/bot.log` + уведомление админу (почта, этап 3).

Команда запуска: `npm run bot` → `node bot/server/index.mjs`.

**Проверка:**
- `node bot/scripts/eval.mjs --dry` — тот же результат, что до этапа.
- Локально: запустить, написать боту в Telegram 5 сообщений (привет, афиша,
  «запишите дочку 7 лет» до конца анкеты, «отмена», вопрос про Симона).
  Заявка появилась в SQLite.
- Скрипты `bot/scripts/n8n-local.mjs`, `build-workflow.mjs`, `poll-telegram.mjs`,
  `bot/workflows/` пока не удалять — удалить после успешного деплоя (этап 5).

## Этап 3. Заявки: почта + SQLite + CSV

- Сервис бота принимает `POST /api/lead` (JSON: тип формы, поля, согласие на ПД).
  Проверка полей, защита от спама (honeypot-поле + не больше N заявок с IP в час).
- Каждая заявка (с сайта и из бота) → таблица `leads` → письмо.
- Почта: `nodemailer`, SMTP ящика театра. Настройки в `.env.bot`:
  `SMTP_HOST=smtp.mail.ru`, `SMTP_PORT=465`, `SMTP_USER`, `SMTP_PASS`
  (пароль для внешних приложений из настроек mail.ru), `LEADS_EMAIL_TO`.
  Отправитель = получатель = ящик театра (так не попадёт в спам).
- Письмо: тема «Заявка: <тип> — <имя>», в теле все поля, откуда (сайт/бот), время.
- `node bot/server/export-leads.mjs [--from=YYYY-MM-DD]` → CSV в UTF-8 с BOM
  (Excel открывает кириллицу правильно).
- Сайт: заменить `submitToSheet` (`src/data/sheetsForms.ts`) на
  `submitLead(type, fields)` → `POST ${VITE_API_BASE}/api/lead`. Формы:
  `SignupForm.tsx`, `FestivalSignupForm.tsx`, `AudienceSignupForm.tsx`,
  `Mascot.tsx`. CORS на сервисе — только домен сайта.
- Уведомления админу, которые раньше шли в Telegram-группу: слать на почту;
  в Telegram — дополнительно, только если с сервера Telegram доступен.

**Проверка:** тестовая заявка с каждой формы сайта и одна из бота → письма
пришли, строки в SQLite, CSV открывается в Excel.
